02 / ПЛАН — ЭТО ЗАВИСИМОСТИ

Кто решает,
что запускать дальше?

RagPlanner выбирает шаги; DagExecutor запускает готовые по depends_on.

Сравни три сервиса рассылок для студии. Нужны условия и вывод. Ничего не покупай.
  1. RagPlanner
  2. Источники A
  3. Критерии B
  4. Сравнение C
  5. Проверка D

Planner видит настроенный roster: описания агентов, skills и tools.

Иллюстрация процесса, не запись запуска.

04 / ГРАНИЦЫ ИНСТРУМЕНТОВ

Промпт просит.
Код проверяет доступ.

Tool allowlist + scopes. Эти ограничения работают на проверяемом пути вызова.

Агент
tools + scopes
↗Разрешённый URL✓
↘URL вне разрешений×

Инструмент должен быть выдан агенту: одной просьбы в промпте мало.

Sandbox-конфигурация и дочерний процесс сами по себе не дают OS-изоляцию.

05 / ПОВТОР ИЛИ НОВЫЙ ПЛАН

Повторить шаг ≠
перестроить план

Сначала retry с задержкой. Затем replan — если остался бюджет.

ЖДЁТ

Сравнение завершилось ошибкой. Проверка ждёт; источники уже собраны.

Есть лимиты попыток, перепланирований и времени шага. Успешный выход процесса не доказывает качество ответа.

06 / СВЯЗАННЫЙ TRACE

От ошибки —
к конкретному вызову

Studio связывает план, шаг и события инструментов в одной записи.

  1. 01plan.created
  2. 02step.started
  3. 03tool.started → tool.completed
  4. 04step.failed / completed
ПЛАН

Запись показывает DAG и выбранных агентов.

Схема формата trace, не запись реального запуска и не скрытые рассуждения модели.

07 / ПАМЯТЬ И РЕЗУЛЬТАТ

Результат сейчас.
Память на потом.

В текущем плане результат идёт по IPC. Долгая память подключается отдельно.

Итог run-agent
compress_and_store
Следующая задача
recall: подходящая сводка

Проверить актуальность

output / summary передаются следующему шагу по IPC даже без базы.

Память опциональна. Если агент не вызвал compress_and_store, возможен fallback на финальный текст.
