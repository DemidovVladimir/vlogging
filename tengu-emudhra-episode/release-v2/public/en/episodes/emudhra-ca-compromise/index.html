02 / TENGU · FIELD STUDY 03

The key that vouches for websites failed

A certificate links a website name to its public key. The issuer signs that link.

  1. 01Trusted issuer → Real website
  2. 02One of the keys: 4
  3. 03Private key → Impersonating site

Normally, only the issuer can produce its digital signature.

Simplified: trust in the issuer follows a chain to a root in the client’s trust store. The encryption algorithm was not broken. Mozilla / incident ↗Ali Mosajjal / analysis ↗RFC 5280 / certificates ↗

03 / TENGU · FIELD STUDY 03

Encrypted. But to the wrong endpoint.

Impersonation needs both: the connection reaches the attacker, and the client accepts the certificate.

  1. 01Your application → Real service
  2. 02Your application → Intermediary
  3. 03Intermediary → Real service
  4. 04Intermediary can read and change data

Normally, your application connects to the real service.

Threat illustration, not a reproduced attack. The CA key alone does not reveal old sessions protected by forward secrecy. RFC 8446 / TLS ↗Cloudflare / response ↗
