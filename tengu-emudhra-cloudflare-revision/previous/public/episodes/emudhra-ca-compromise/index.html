03 / TENGU · FIELD STUDY 03

Два сертификата. Один опасный ключ.

Cross-signing: тот же открытый ключ заверен другой цепочкой издателей.

  1. 01Маршрут emSign → Промежуточный CA · ключ Q
  2. 02Маршрут Sectigo / AAA → Другой сертификат · тот же Q
  3. 03Блокировка по ключу закрывает оба пути

Клиент строит цепочку от сертификата сайта к доверенному корню.

Схема двух маршрутов, промежуточные звенья сокращены. Доступность пути зависит от trust store клиента. Ali Mosajjal / analysis ↗Dennis Jackson / checks ↗Google / response ↗RFC 5280 / certificates ↗

04 / TENGU · FIELD STUDY 03

Шифрование есть. Собеседник — не тот.

Для подмены нужны две вещи: соединение приходит к атакующему, а клиент принимает его сертификат.

  1. 01Твоё приложение → Настоящий сервис
  2. 02Твоё приложение → Посредник
  3. 03Посредник → Настоящий сервис
  4. 04Посредник видит и меняет данные

Обычно приложение соединяется с настоящим сервисом.

Схема риска, не воспроизведённая атака. Ключ CA сам по себе не раскрывает старые сессии с прямой секретностью. RFC 8446 / TLS ↗Dennis Jackson / checks ↗
