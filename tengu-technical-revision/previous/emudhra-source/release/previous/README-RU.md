## Приватность

**Публиковать только отдельный проверенный публичный снимок сайта. Текущий baseline — `public/` + `build-manifest.json`.** Старый `build.mjs` предназначен только для EP.01, не запускать его для следующего выпуска.

Не загружать исходный `tengu-agent-context-deck/dist`: в нём есть сценарии и режиссёрские планы.
Не загружать рабочую папку целиком, `tengu-youtube-kit`, `.codex`, `.claude`, Git-историю или архив навыка.
Сборщик использует явный список файлов и останавливается при неожиданном файле в `public/`.
Шрифты опубликованы с OFL-лицензиями. Публичные JS содержат интерактивность, а не дикторские сценарии.
`404.html` отключает SPA-подстановку: отсутствующие приватные пути действительно возвращают 404.
Приватность обеспечивается отсутствием файлов в загрузке, а не скрытыми ссылками или robots.txt.
Существующая публикация Sites и её настройки доступа не менялись.

Публикация выполнена через Cloudflare MCP и официальный Pages Direct Upload API:

1. Проверить аккаунт и существующий проект `tengu-presentations`; не создавать дубликат.
2. Получить краткоживущий JWT через `GET /accounts/{account_id}/pages/projects/tengu-presentations/upload-token`.
3. Подготовить загрузчик под проверенный полный inventory. Исторический `upload-assets.mjs` в этой папке ограничен 33 файлами; не использовать его для нескольких выпусков. Адаптированный загрузчик EP.02 находится в `../tengu-cluster-episode/release/upload-assets.mjs` и ожидает 85 статических файлов. Передавать JWT только через stdin с отключённым echo; никогда в аргументах, файлах, логах или чате.
4. Загрузчик проверяет allowlist и SHA-256, загружает весь статический снимок, создаёт локальный `upload-manifest.json`. `_headers` и `_redirects` передаются отдельно. Перед загрузкой обязателен `audit-public.mjs` с предыдущим manifest; не ослаблять аудит ради числа файлов.
5. Создать production deployment через `POST /accounts/{account_id}/pages/projects/tengu-presentations/deployments`, multipart: `manifest`, `branch=main`, сведения об исходном commit, `_headers` и `_redirects` как текстовые файлы. Functions/Workers не используются.
6. Дождаться `latest_stage.status=success`, проверить оба языка и приватные пути. Обновить локальный `deployment-record.json`.

Протокол загрузчика сверён с официальным `cloudflare/workers-sdk`, Wrangler 4.151.3 (`pages/upload.ts`, `deploy-helpers`).
