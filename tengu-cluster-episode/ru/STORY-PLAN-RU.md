# TENGU EP.02 — Режиссёрский план

История: уверенного ответа мало → связанный план → нужный контекст → реальные границы → обработка сбоя → наблюдаемость → память → критерий полезности. Все примеры постановочные, не результаты замера.

## 00 / Интро — 00:00–00:03

Нажать запуск, дать закончиться MP4 со звуком.

## 01 / Как устроен наш Tengu Cluster — 00:03–00:38

Фазы (R, затем → по мере объяснения):

- config.toml → planner → executor
- run-agent → tool call → результат шага

## 02 / Кто решает, что запускать дальше? — 00:38–01:16

Фазы (R, затем → по мере объяснения):

- Planner видит настроенный roster: описания агентов, skills и tools.
- A и B не зависят друг от друга — executor запускает их параллельно.
- C: depends_on = [A, B]. Пока оба не готовы, сравнение не начнётся.
- D получает результат C. Простой запрос может обойти план: Direct.

## 03 / Один шаг плана — отдельный процесс — 01:16–01:54

Фазы (R, затем → по мере объяснения):

- Родитель передаёт цель, результаты зависимостей и план этой сессии.
- Дочерний процесс загружает конфигурацию выбранного агента.
- Внутри идёт цикл модели и инструментов. Итог возвращается как JSON.

## 04 / Промпт просит. Код проверяет доступ. — 01:54–02:34

Фазы (R, затем → по мере объяснения):

- Инструмент должен быть выдан агенту: одной просьбы в промпте мало.
- Scope дополнительно проверяет аргументы: например, адрес или путь.
- Shell, браузер и native tools CLI требуют собственных ограничений.

## 05 / Повторить шаг ≠ перестроить план — 02:34–03:14

Фазы (R, затем → по мере объяснения):

- Сравнение завершилось ошибкой. Проверка ждёт; источники уже собраны.
- Retry повторяет тот же шаг с задержкой, пока остаются попытки.
- Replan меняет план. *Готовый результат сохраняется лишь при совпадении шага и зависимостей.

## 06 / От ошибки — к конкретному вызову — 03:14–03:50

Фазы (R, затем → по мере объяснения):

- Запись показывает DAG и выбранных агентов.
- session_id и step_id связывают работу дочернего процесса.
- События вызовов возвращаются в trace родителя под своим шагом.
- Studio воспроизводит запись событий. Инструменты заново не запускаются.

## 07 / Результат сейчас. Память на потом. — 03:50–04:28

Фазы (R, затем → по мере объяснения):

- output / summary передаются следующему шагу по IPC даже без базы.
- При включённой памяти сводка сохраняется в Postgres + pgvector.
- Recall добавляет релевантные записи в новый контекст, не меняя веса модели.

## 08 / Не «толпа агентов». Управляемое выполнение. — 04:28–05:02

Фазы (R, затем → по мере объяснения):

- config.toml: кто и с какими правами
- DAG + IPC: как идёт работа
- Trace + проверка: почему доверяем итогу

## Управление и запись

- P: pause/resume; R: reset paused; ← / →: phase back/forward, paused.
- − / +: 0.25×–2×; 0: normal speed.
- Down / PageDown / Space: next; Up / PageUp / Shift+Space: previous. Home / End: intro / closing.
- Wheel / touch: natural scroll. Hidden tabs freeze diagrams. Reduced motion: final phase, manual stepping still works.
- Diagrams hold their final phase rather than looping. Controls do not scrub the MP4.
- Record the deck only. Keep script.html and ?view=plan in a separate LOCAL window/device.
- Timing is a rehearsal target, not auto-advance. Slow down on the plan and permission boundary; do not read source links aloud.
